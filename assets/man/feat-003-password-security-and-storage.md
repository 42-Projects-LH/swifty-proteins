# Feature: Password Security & Storage

## Overview
Guarantees multi-tier cryptographic protection of user credentials, ensuring that passwords and sensitive authentication data are never exposed or stored in plain text, immunized against rainbow-table attacks with unique cryptographic salts, and encrypted at rest with hardware-backed Android KeyStore AES-256.

---

## Evaluation Requirements
* **No Plaintext Passwords**: Verify that passwords are never stored in plain text under any circumstances.
* **Platform Secure Storage**: Utilization of platform-specific hardware-backed secure storage (Android KeyStore / Keychain on iOS).
* **Cryptographic Hashing & Salting**: Application of industry-standard cryptographic hashing algorithms (salted SHA-256 / PBKDF2) prior to storage.

---

## Technical Specifications
* **Cryptographic Salting (`SecureRandom`)**:
  * Each registered user receives a unique 16-byte (128-bit) cryptographically strong pseudo-random salt generated by `java.security.SecureRandom`.
  * **Rainbow Table Immunity**: Because every user's salt is unique, precomputed rainbow table dictionaries cannot crack stored digests, and identical passwords produce completely different hash strings.
* **Password Hashing Pipeline**:
  * Algorithm: Salted SHA-256 (`MessageDigest.getInstance("SHA-256")`).
  * Process:
    $$\text{Hash} = \text{SHA-256}(\text{Salt}_{\text{hex}} \,\|\, \text{Password}_{\text{UTF-8}})$$
  * Stored representation: `"$saltHex:$hashHex"` (32-hex-character salt + 64-hex-character digest).
* **Hardware-Backed Key Management**:
  * Android KeyStore Provider: Stores cryptographic master keys inside hardware-isolated secure enclaves (TEE / StrongBox when available).
  * `MasterKey.Builder` with `AES256_GCM` scheme.
* **Encrypted Storage at Rest**:
  * Jetpack Security library: `androidx.security.crypto:security-crypto`.
  * `EncryptedSharedPreferences`:
    * Key Encryption: `AES256_SIV` (deterministic synthetic IV for key lookups).
    * Value Encryption: `AES256_GCM` (authenticated ciphertext with integrity verification).
* **Validation & Migration**:
  * During login, the user's salt is extracted from `EncryptedSharedPreferences`, and the entered password is salted and hashed to compare against the stored digest.
  * Backward compatibility: Legacy unsalted entries are validated and automatically upgraded to salted hashes upon successful login.

---

## Security Architecture Flow
```
[ User Registers Password ]
           │
           ▼
[ SecureRandom Generates 16-Byte Cryptographic Salt ]
           │
           ▼
[ Salted SHA-256 Hashing: Hash(Salt + Password) ]
           │
           ▼
[ Composite Record: "$saltHex:$hashHex" ]
           │
           ▼
[ Android KeyStore Hardware MasterKey (AES256_GCM) ]
           │
           ▼
[ EncryptedSharedPreferences (AES256_SIV / AES256_GCM) ]
           │
           ▼
[ Encrypted File on Disk: /data/data/.../secure_user_prefs.xml ]
```

## Verification & Testing
1. **Code Inspection**: Confirm `SecureStorage.kt` generates a 16-byte random salt using `SecureRandom` and computes salted SHA-256 before disk writes.
2. **Device Inspection**: Inspect `/data/data/com.example.swiftyproteins/shared_prefs/secure_user_prefs.xml`; confirm both keys and values are encrypted ciphertext backed by the Android KeyStore master key.
3. **Collision Resistance**: Register two different accounts with the exact same password (e.g. `password123`); verify that their stored salted hashes are completely distinct.
